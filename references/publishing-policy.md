# Publishing Policy

## Approval

- Draft/save-to-draft actions are external writes. Ask for confirmation unless the user explicitly requested draft creation for exact targets.
- Public publish/group send actions always require a final explicit confirmation naming content and targets.
- If the user says “直接发布”, still summarize exact targets and ask for final confirmation unless the content was already finalized in the same turn.

## Privacy and Credentials

- Never display cookies, tokens, AppID/AppSecret, OAuth secrets, or browser session artifacts.
- Use first-class skills/tools when available; do not invent CLI commands.
- Do not bypass login, CAPTCHA, platform review, rate limits, or safety checks.

## Failure Handling

- Record each target result independently.
- If one target fails after others succeed, report the partial state clearly.
- Stop when an ambiguity could cause wrong-account or wrong-platform publishing.

## Content Integrity

- Preserve factual claims across adaptations.
- Mark platform-specific rewrites clearly when showing previews.
- Avoid adding promotional claims, investment advice, medical/legal claims, or copyrighted media without user approval.
